# 実装の構成図

2026-09-27 の作業ツリーに基づく概略図。過去の実験時の設定・版を保証するものではない。

## 図の整理

- 事前準備と反復処理を分離。
- 反復は Unity → 検査・評価 → 更新判断 → 修正処理 → scene JSON → Unity。
- 最良状態の出力は反復とは別の出口に配置。
- 全景8視点と物体ごと3方向を区別。
- モデル数、誤検出率、比較基準の詳細はこの概略図から省略。

## 元のスライドとの相違

- 拡写「48枚／1物体1枚」は、モデル資産数と撮影対象数を混同するおそれがある。詳細撮影は対象物体ごとに3方向。
- orchestrator.py:454 付近では機械違反数が同点の際、VLMによる画像の前後比較を巻き戻し判断に使う。
- orchestrator.py:528 付近では全景スコアの収束を停止判断に使う。
- orchestrator.py:381 付近で全景評価の worst_object と b3_defects を取得し、修正処理に渡す経路がある。
- repair.py:1071 以降にはVLM由来の向き・浮遊・モデル差し替えの修正経路がある。実際に適用されるかは候補と条件による。
- 詳細VLMの修正利用は既定では無効。detail_vlm_repair が有効な場合に候補を渡す。
- 詳細監査は既定では機械違反ゼロ時。毎反復の監査は設定による。
- 最良状態の比較順は機械違反数、縦横比誤差、詳細監査fail数。監査にuncertainがある場合はfail数を比較に渡さない。

## 画像生成

Built-in image_genを使用。生成指示: 白背景の16:9日本語学術スライド。タイトル「実装の構成」。事前準備は画像生成、3Dモデル生成、正面方向の登録。反復処理はUnity、検査・評価、更新判断、修正処理、scene JSONを循環接続し、終了時に最良状態を出力。青は主要処理、黄はVLM。全景8視点／物体ごと3方向。詳細VLMの修正利用は設定で切替。

最終編集指示: 画像生成からUnityへ直接入る矢印を除去し、準備の帯と反復を分離。他は維持。

### 12.12 10/10 実測 — 光のループのものさしと、照明の作り直し（案）

この節は 10/10 の実測と、その日に決めたこと。12.3 の「つまみ」と「違反 → 手」の表は、この節の結果で一部が成り立たなくなった（12.12.6）。

#### 12.12.1 ものさし（参照写真と計算）

- 写真: Places365-Standard の**学習用** data_256、`h/home_office`（5000枚）から seed=0 で100枚（検証用 val_256 は未取得）。論文で使う段階で val や校正済みデータにそろえるかは未定
- 計算: `mvl-skeleton/python/light_metrics.py`。写真も全景も 256×256 に縮めて同じ関数で計算（Places の val_256/data_256 は縦横比を無視した 256×256）
- L1 = 平均色（線形RGB）→ xy → McCamy の式（自作）。L2 = 輝度 Y'（ガンマ後）の中央値。L3 = Y' の標準偏差。L4 = Y' ≥ 0.99 / ≤ 0.01 の割合
- **決定: L4 は上限だけを違反にする**（白飛び・黒つぶれが「少ない」ことは違反にしない。12.3 の違反表も「多い」側のみ）
- 結果出力: `research/places365/out_<ラン名>/summary.csv`

| 項目 | 写真 P10 | P50 | P90 |
|---|---|---|---|
| L1 色温度 [K] | 4196 | 5554 | 6551 |
| L2 輝度中央値 | 0.218 | 0.414 | 0.628 |
| L3 標準偏差 | 0.191 | 0.256 | 0.302 |
| L3 対数版（12.12.7） | 0.519 | 0.817 | 1.13 |
| L4 白飛び＋黒つぶれ | 0.0009 | 0.012 | 0.059 |

同じ光で撮り直すと値は小数4桁まで一致した。**この物差しは試行間でぶれない**（VLM の ±0.4、§6.1 と対照的）。

#### 12.12.2 9/15 のラン（seed2 0915_174649、殻は単色）

L1 4197K（範囲内 4/8、オレンジ寄り）、L2 7/8、L3 4/8（眠い側）、L4 は白飛びゼロ。

#### 12.12.3 L1 のオレンジ寄りは主に光の色

seed1・4096 で、殻と光だけを変えて比較。

| 条件 | L1 中央値 | 範囲内 |
|---|---|---|
| A 殻単色・光 `FFE8C8` | 4303K | 6/8 |
| B 殻テクスチャ・光 `FFE8C8` | 4209K | 5/8 |
| C 殻テクスチャ・光 `FFFFFF` | 5167K | 8/8 |

- 殻を替えても約90K、光を白にすると約960K 動いた。残りの約400K（写真 P50 との差）は床・家具の木の色と見ている（素材のみの計算: `wall.png` 5817K、`floor.png` 3213K）
- 光の色は L1 のつまみとして効く

#### 12.12.4 環境光のつまみは効いていない

- `ambient_intensity` 0.9 / 0.6 / 0.3 で L1〜L4 がほぼ同一（画素差の平均 0.25/255）。値はシーンJSON・コード（`SetupLighting` 470〜471行）まで届き、ベイクも毎回やり直されている
- 見立て（未確認）: 閉じた箱の部屋では、ベイク時に環境光（空からの光）が室内に届かない
- → 12.3 の「環境光 ±1」は手として使えない

#### 12.12.5 太陽の影がオフだった（全ランに影響）

- `SceneBuilder.cs` の `SetupLighting` が `light.shadows` を設定しておらず、太陽は**影なし**だった。光が壁・天井を素通りして部屋全体を照らしていた（`AssetStudioCapture.cs` 408行は `Soft` を明示している）
- `light.shadows = LightShadows.Soft;` を追加すると、窓のない箱は真っ暗になった（L2 0.112、L3 0.057、L1 8217K、すべて 0/8）
- **10/10 午後の「光を白・強さ 1.8 で L1〜L4 がほぼ範囲内」は、光が素通りした状態での結果なので引き継がない。** 確かめられたのは「光の色と強さのつまみが効く」「1つのつまみが複数の項目を動かす（強さ 1.3→1.8→2.5 で L3 は改善、L2・白飛びは悪化）」の2点のみ
- 10/10 時点のコードには影の設定が無かったので、9/15 以前のラン（図1・検出率の測定を含む）も影なしで撮られていた可能性が高い。いつから無かったかは git の履歴で要確認。数値の扱いもそれから考える

#### 12.12.6 窓と天井照明の実装

コード変更（`XRunity/Assets/Editor`）:

- `MVL.cs`: `Window`（wall / center / width / height / sill_height / asset）、`CeilingLight`（intensity / color_hex / range / asset / fixture_width / fixture_height / fixture_emission）を追加。`Room.window`、`Lighting.ceiling_light`。JSON に書かなければ無効（既存シーンは変わらない）
- `SceneBuilder.cs`:
  - `light.shadows = LightShadows.Soft`（太陽）
  - `MakeWallWithWindow`: 壁を窓の穴の周り4枚で作る（現状 `E` と `S` の壁のみ）
  - `SetupCeilingLight`: 部屋中央・天井下に点光源（影あり、Mixed）
  - `PlaceFixtures`: 窓・天井器具の GLB を `PlaceObject` で置く。**`report.objects` に入れないので機械検査とループの対象外**
  - 殻の光漏れ修正: 床・天井・北壁・西壁を壁の厚みぶん延ばして角のすき間をふさいだ

モデル（`scene/assets/1010/`、gpt-image-2 low → TRELLIS.2）:

- `window_v1`・`v3` はガラス部分が穴。**`window_v2` はガラスが板になっていて光を通さない（使用不可）**
- 使用: `window_v1`（幅1.0 × 高さ1.35、下端0.9、東の壁中央）、`ceiling_light_v1`（直径0.35 × 高さ0.15、器具は影を落とさない設定）

| 条件（光 白・太陽 1.8・影あり） | L1 | L2 | L3 | L4 |
|---|---|---|---|---|
| 窓のみ（仮の穴） | 6921K 3/8 | 0.135 0/8 | 0.112 1/8 | 8/8 |
| 窓＋天井照明（仮の箱） | 5771K 8/8 | 0.387 8/8 | 0.162 2/8 | 8/8 |
| 窓＋天井照明（モデル） | 5800K 8/8 | 0.379 8/8 | 0.156 0/8 | 8/8 |

見た目: 窓の形の日だまりが床に出る。窓のみでは日だまりの周りがほぼ真っ暗（間接光が弱い）。窓の外は Unity 既定の空（L0 未実装）。

#### 12.12.7 L3（コントラスト）の定義の問題

- 天井照明 1.0 → 0.6 にすると L3 は 0.156 → 0.134 に**下がった**（予想は上昇）。太陽 1.8 → 2.4 はほぼ変化なし（日だまりが画面の一部しかないため）
- 原因: L3（Y' の標準偏差）は部屋全体の明るさに比例して縮む。コントラストと明るさが混ざっている
- 試験的に `L3_logstd = std(log(Y' + 0.01))` を追加:

| ラン | L3 標準偏差 | L3 対数版 |
|---|---|---|
| 影なし（白・1.8） | 0.235（8/8） | 0.524（4/8） |
| 窓＋天井（仮の箱） | 0.163（2/8） | 0.507（4/8） |
| 窓＋天井（モデル） | 0.156（0/8） | 0.498（3/8） |
| 天井照明 0.6 | 0.134（0/8） | 0.461（3/8） |
| 太陽 2.4 | 0.156（0/8） | 0.497（3/8） |

- 明るさによる低下は 14% → 7% に縮んだが、ゼロではない（+0.01 とトーンマッピングのため）。影なしの部屋を合格させなくなり、「どの部屋も実写よりのっぺり」という目視と合う
- 出典: 標準偏差版は Peli (1990) の RMS コントラストとして引用できる。**対数版と同じ定義の出典は見つかっていない**。どちらを採るかは、校正済みデータで比べてから決める（両方を残す）

#### 12.12.8 方針: 「違反 → 手」の固定表をやめる

本物らしい光（影・窓・天井照明）にすると、12.3 の表（環境光・太陽で L3 を直す）が成り立たなかった。部屋が変わるたびに人が表を作り直すのではなく、**ループ自身が「つまみを1段動かす → 測る → 良ければ採用、悪ければ巻き戻して禁止」で効くつまみを見つける**。巻き戻しと禁止は幾何のループで動いている仕組みと同じ。

今の部屋の課題は明暗の差が足りないこと。つまみの候補: 天井照明の強さ、デスクランプ・フロアランプの点灯（局所の光だまり）、太陽、窓の大きさ、光の色。

#### 12.12.9 その他

- **Unity の時間**: 器具モデル入りで1周 約230秒（GLB 40MB 前後の読み込み・軽量化。キャッシュが効いていない）。器具なしの4096版は 32〜38秒、初回 75秒。§6.4 の見積もりに直接効く
- **天井器具の発光が効かない**: glTFast のシェーダーで `emissiveFactor` を設定しても画面に出なかった。GPT の調査では glTFast は `_EMISSIVE` キーワードで有効化する（こちらは `_EMISSION` のみ）。未検証。見た目の仕上げなので優先度は低い
- Unity エディタで XRunity を開いたままバッチ実行すると、0〜2秒で exit=1 になる（10/10 に2回発生）
